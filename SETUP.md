# Rebuilding the reference databases

`Resources/food.db` and `Resources/exercises.db` are generated by
`Tools/build_reference.py` from raw public data dumps. You should not need
to run this unless you're expanding the food data or the source data has
changed — `food.db` is committed directly (it's small, see below), so a
normal checkout already has it.

## food.db — phase 1 (current): USDA Foundation Foods + SR Legacy

No Open Food Facts, no branded products, no FNDDS survey data yet — just
USDA's two smallest, highest-quality generic/whole-food datasets. ~9,800
input rows, ~7,928 survive the calories-required filter, ~1.5MB output.

1. Download both from <https://fdc.nal.usda.gov/download-datasets> (no
   account needed) — the CSV version of each:
   - **Foundation Foods**
   - **SR Legacy**
2. Unzip both. Each contains its own `food.csv` and `food_nutrient.csv`
   with identical headers.
3. Merge them into one `food.csv` and one `food_nutrient.csv` under
   `data/fdc/` (concatenate, keep only one header row —
   `build_reference.py`'s `main()` rebuilds `food.db` from scratch on every
   run via `fresh_db()`, so it must see all the data in one pass, not two
   separate runs against two separate source directories). A quick way:

   ```python
   import csv
   def merge(sources, out_path):
       writer = None
       with open(out_path, "w", newline="", encoding="utf-8") as out_f:
           for path in sources:
               with open(path, newline="", encoding="utf-8") as in_f:
                   reader = csv.DictReader(in_f)
                   if writer is None:
                       writer = csv.DictWriter(out_f, fieldnames=reader.fieldnames)
                       writer.writeheader()
                   for row in reader:
                       writer.writerow(row)
   ```

4. Run the build script:

   ```bash
   python3 Tools/build_reference.py --sources data --out Tools/out
   ```

   (it expects `data/fdc/food.csv` and `data/fdc/food_nutrient.csv` —
   `load_off()` looks for `data/off/en.openfoodfacts.org.products.csv` and
   silently skips Open Food Facts entirely if that file is absent, which is
   exactly phase 1's intent.)

5. Copy the result into the app bundle:

   ```bash
   cp Tools/out/food.db Resources/food.db
   ```

6. Regenerate the Xcode project (`make project`) and rebuild — `Resources/`
   is already wired as a source path for the `Lift` target in
   `project.yml`, so no project.yml change is needed; XcodeGen bundles
   everything under it automatically, the same way `Resources/exercises.db`
   already ships.

## food.db — phase 2 (not yet done): Open Food Facts + branded/barcode data

Deferred deliberately — see
`docs/superpowers/specs/2026-09-08-gram-based-serving-design.md` in the
`LIFT` superproject repo for the full reasoning. To add it later:

1. Download a full Open Food Facts export (tab-delimited CSV,
   `en.openfoodfacts.org.products.csv`) from
   <https://world.openfoodfacts.org/data> — multi-GB, restricted by
   `OFF_COUNTRIES` in the script to US/CA/UK products.
2. Place it at `data/off/en.openfoodfacts.org.products.csv`.
3. Re-run step 4 above — `load_off()` will pick it up automatically
   alongside the existing USDA data (nothing else changes).

This will grow `food.db` substantially (likely several hundred MB) — at
that point, re-add `Resources/food.db` to `.gitignore` and switch to Git
LFS or a CI build step instead of committing it directly, per the note
already left in `.gitignore`.

## exercises.db

Same script, separate output file — see `Tools/build_reference.py`'s
`load_exercises()` for its own two sources
(`data/exercises/free-exercise-db.json`, already committed, plus an
optional `data/exercises/wger-exercises.json` pulled from the wger API).
Not part of this project's scope; already working today.

## Licensing

`food.db` mixes USDA FoodData Central (public domain) with, eventually,
Open Food Facts (ODbL, share-alike) — see the big comment at the top of
`Tools/build_reference.py` for why these stay in one file only once both
are present, and `ATTRIBUTION.md` for the attribution text to ship once
Open Food Facts data is actually included. Phase 1 (USDA only) needs no
attribution — public domain data has none legally required — but
`ATTRIBUTION.md` already carries the boilerplate for when phase 2 lands.
